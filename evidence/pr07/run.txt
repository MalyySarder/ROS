ПР07 — Gazebo и мост ros_gz

Суть
Запущен мир mcity_minimal с машиной course_ackermann. ROS и Gazebo используют
разные транспорты; ros_gz_bridge передаёт поддерживаемые сообщения между ними.
Наш адаптер переводит угол руля Ackermann в угловую скорость Twist:
  /drive/safe -> ackermann_adapter -> /vehicle/gz_cmd_vel -> bridge -> Gazebo.
Скорость ограничена 0..1.2 м/с, угол ±0.45 рад; omega = v*tan(delta)/0.8.
При NaN/inf, старой команде (>0.25 с), пропадании команд — нулевой Twist.
Команда из будущего также отклоняется. При v=0 машина не крутится на месте.
/drive/raw никуда не подключён: supervisor появится в следующей работе.

Обратный путь:
Gazebo -> bridge -> /vehicle/odom_gz -> odom_adapter -> /vehicle/odom и /tf.
Frames course_ackermann/odom и course_ackermann/base_link заменяются на
odom и base_link. Stamp, pose, twist и обе covariance сохраняются.
Статические связи сенсоров публикует robot_state_publisher из ПР06.

ackermann_msgs, geometry_msgs, nav_msgs, tf2_ros, Xacro, robot_state_publisher,
rosbag2/MCAP, pytest/colcon. Headless-рендерер: OGRE2/EGL.

Демонстрация — терминал 1
  ros2 launch course_simulation simulation.launch.py headless:=true
Оставить работающим. Один launch запускает сервер Gazebo, один bridge,
robot_state_publisher и два адаптера. Не запускать второй мост отдельно.
Для графического окна Gazebo вместо headless:=true поставить headless:=false.

Терминал 2 — сначала данные, затем управление
  ros2 node list
  ros2 topic echo /clock --once
  ros2 topic echo /vehicle/imu --once --field header
  ros2 topic hz /vehicle/scan
После нескольких строк остановить hz через Ctrl+C.
  ros2 topic info -v /vehicle/imu
Показать BEST_EFFORT/KEEP_LAST; для /vehicle/odom — RELIABLE.

Свежая команда, скорость 0.3 м/с, прямое движение:
  ros2 topic pub -r 20 --use-sim-time /drive/safe ackermann_msgs/msg/AckermannDriveStamped '{header: auto, drive: {speed: 0.3, steering_angle: 0.0}}'
header:auto заполняется текущим ROS-временем; --use-sim-time берёт его из /clock.
Достаточно 3–5 секунд, затем Ctrl+C. Не держать команду до столкновения со стеной.
Для короткого поворота заменить steering_angle: 0.0 на steering_angle: 0.2.
После остановки источника watchdog обнулит команду. Явный стоп:
  ros2 topic pub --once --use-sim-time /drive/safe ackermann_msgs/msg/AckermannDriveStamped '{header: auto, drive: {speed: 0.0, steering_angle: 0.0}}'

Терминал 3 — пока терминал 2 публикует движение
  ros2 topic echo /vehicle/gz_cmd_vel --once
  gz topic -e -t /model/course_ackermann/cmd_vel -n 1
  ros2 topic echo /vehicle/odom --once
  gz topic -e -t /world/mcity_minimal/dynamic_pose/info -n 1
Повторить две последние команды: изменяются и одометрия, и физическая поза
course_ackermann. В динамических позах видны ориентации колёс и рулевых кулаков.
  ros2 run tf2_ros tf2_echo odom base_link --ros-args -p use_sim_time:=true
Остановить через Ctrl+C. TF совпадает с pose одометрии.
  ros2 run tf2_ros tf2_echo base_link lidar_link --ros-args -p use_sim_time:=true
Ожидается translation [0.28, 0, 0.38]. Аналогично camera_link и imu_link.

Преднамеренная неисправность
1. Ctrl+C в терминале 1, дождаться остановки ВСЕХ его процессов.
2. Запустить тот же launch с ошибочной копией YAML:
  ros2 launch course_simulation simulation.launch.py bridge_config:=$PWD/src/course_simulation/config/bridge_fault.yaml
3. В другом терминале:
  ros2 topic info -v /vehicle/imu
  timeout 4s ros2 topic echo /vehicle/imu --once
  gz topic -i -t /vehicle/imu
  gz topic -e -t /vehicle/imu -n 1
ROS-издатель есть, но echo завершается по таймауту (код 124).
Gazebo выдаёт IMU на /vehicle/imu, а faulty YAML слушает /vehicle/imu_typo.
4. Остановить ошибочный launch, запустить обычный из раздела «терминал 1».
  ros2 topic echo /vehicle/imu --once --field header
Данные снова приходят. Второй bridge параллельно не создаётся.

Запись для ПР08
fixtures/pr07-sensors — сохранённый локальный вход; НЕ перезаписывать его.
Для собственной демонстрационной записи использовать новое имя, например:
  ros2 bag record --storage mcap --use-sim-time -o fixtures/pr07-sensors-demo --topics /vehicle/camera/image_raw /vehicle/scan /vehicle/imu /vehicle/odom /tf /tf_static /clock
Дождаться увеличения /clock минимум на 32–35 секунд и остановить recorder Ctrl+C.
  ros2 bag info fixtures/pr07-sensors-demo
Нужны duration >=30 секунд и ненулевые счётчики всех семи топиков, включая
/tf_static. Из-за RTF время ожидания на компьютере может быть больше.
Камера, лидар и IMU — best effort; часть кадров может пропускаться под нагрузкой.

Что сдавать и где смотреть доказательства
report.json — отчёт курса и SHA коммита реализации;
sensors.json — frames, частоты по времени компьютера/симуляции и RTF;
headless.txt — запуск, команды и реальные результаты опытов;
odom-adapter.md — контракт одометрии, владельцы TF, проверка сохранения данных;
bag-info.txt — длительность и состав MCAP; workstation.txt — среда и рендерер.
Большая запись MCAP оставлена локально, в Git не загружается.
Проверка курса выполняется на чистом checkout коммита сдачи:
  python3 .course-kit/v1/tools/check_practice.py PR07 --submission .
В рабочей папке посторонние незакоммиченные файлы могут мешать проверке чистоты.
